invgen user guide

Introduction

invgen turns invoices written in markdown into clean PDFs.

  • Your data lives once in a config file. Who you are, your bank details and your clients go into ~/.config/invgen/config.yaml. An invoice file only says what changes: the date, the client and the line items.
  • A native Linux editor shows a live preview of the PDF as you type, lists your invoices in a sidebar and exports with one shortcut.
  • A small CLI creates, builds, watches and lists invoices from the terminal, so invgen also fits scripts, Makefiles and your own text editor.
  • Plain text files. Invoices are markdown with YAML front matter. They diff well, live happily in git and stay readable without invgen.

A complete invoice can be this short:

---
number: EINV-2026-23
date: 2026-11-02
client: northwind
---

| Description              | Qty | Unit | Rate   |
|--------------------------|-----|------|--------|
| Senior Software Engineer | 21  | days | 450.00 |

How this guide is organized

  • Install and Quickstart get you from nothing to a first PDF.
  • The reference chapters describe the configuration file, the invoice format, every command and the editor.
  • The recipes show complete workflows, starting with monthly billing for one client.
  • FAQ and troubleshooting covers Flatpak file access, fonts and where the config lives.

invgen is MIT licensed. Source, issues and releases: https://github.com/ldolberg/invgen. Want to help? Read CONTRIBUTING.md.

Install

invgen runs on Linux. Pick one of the three options below; all of them read the same config file (~/.config/invgen/config.yaml).

Flatpak

Works on any distribution and updates with flatpak update:

flatpak install --user https://ldolberg.github.io/invgen/io.github.ldolberg.invgen.flatpakref

The repository is signed and self-hosted on GitHub Pages; the install page has the details. Launch the editor from your desktop menu, or from a terminal:

flatpak run io.github.ldolberg.invgen                  # the editor
flatpak run io.github.ldolberg.invgen build FILE.md    # any CLI command

A shell alias makes the CLI feel native:

alias invgen='flatpak run io.github.ldolberg.invgen'

The sandbox can read and write ~/Documents and ~/.config/invgen. Files elsewhere can still be opened through the file chooser; see Flatpak file access.

Prebuilt tarball (x86_64)

Download invgen-vX.Y.Z-x86_64-linux.tar.gz from the releases page, check it against the .sha256 file next to it, then:

tar xzf invgen-*-x86_64-linux.tar.gz && ./invgen-*/install.sh

The tarball also contains the format spec, an example config and example invoices.

From source

You need Rust 1.85 or newer.

git clone https://github.com/ldolberg/invgen
cd invgen
make install      # binary to ~/.local/bin, desktop entry and icon to ~/.local/share

make uninstall removes them again. To install only the binary:

cargo install --path . --locked

Make sure ~/.local/bin (or ~/.cargo/bin) is on your PATH.

Check the install

invgen --version
invgen --help

Quickstart

This walks through a first invoice. The names and numbers are examples; use your own.

1. Create the config

invgen config --edit

This creates ~/.config/invgen/config.yaml with commented placeholders and opens it in $VISUAL or $EDITOR (nano when neither is set). Fill in your name, address, bank details and at least one client:

invoices_dir: ~/Documents/Invoices
number_prefix: INV
currency: EUR
tax_rate: 0
due_days: 14

from:
  name: Alex Morgan
  address: [Rue de la Gare, Luxembourg, "1616", Luxembourg]
  tax: ["VAT ID: LU12345678"]
  email: alex@example.com

payment:
  holder: ALEX MORGAN
  iban: DE89 3704 0044 0532 0130 00
  bic: COBADEFFXXX

clients:
  northwind:
    name: Northwind Labs SL
    address: ["Calle Mayor, 12", Madrid, "28001", Spain]
    tax: ["Tax ID: B12345678"]
    rate: 450
    unit: days
    description: Senior Software Engineer

When you close your text editor, invgen loads the file again and warns about mistakes. See Configuration for every key.

2. Create an invoice

invgen new --client northwind

invgen prints the path of the new file, for example ~/Documents/Invoices/INV-2026-01.md. The number is the next free one in your invoices directory. The file is prefilled for last month: one line item using the client’s description, unit and rate, and a quantity equal to the number of weekdays (Monday to Friday) in that month.

3. Edit it with a live preview

invgen edit ~/Documents/Invoices/INV-2026-01.md

Change the quantity, add rows, write a note. The preview on the right updates as you type, and mistakes are shown with their line number. invgen new --client northwind --open does steps 2 and 3 in one go.

4. Build the PDF

Press Ctrl+E in the editor, or from a terminal:

invgen build ~/Documents/Invoices/INV-2026-01.md

The PDF is written next to the markdown file and named after the invoice number: INV-2026-01.pdf.

5. Keep track

invgen list

shows every invoice in the invoices directory with its date, client, total and status, plus a total per year. When a client pays, change status: pending to status: paid in the file.

Configuration

Everything that stays the same from one invoice to the next lives in one YAML file: who you are, how to pay you, your clients and a few defaults.

Where the file lives

SituationPath
Default~/.config/invgen/config.yaml (or $XDG_CONFIG_HOME/invgen/config.yaml when that variable is set)
FlatpakAlways ~/.config/invgen/config.yaml, shared with the native build
--config PATH on any commandPATH
INVGEN_CONFIG=PATH in the environmentPATH (--config wins when both are given)

invgen config prints the path in use and creates a commented starter file there if none exists. invgen config --edit also opens it in $VISUAL or $EDITOR (falling back to nano) and validates the result when you close the editor.

Without a config file invgen still works, with built-in defaults and no sender, bank or clients. An empty file behaves the same way.

Precedence

For each invoice, currency, tax_rate, tax_note and language are taken from the first place that sets them:

  1. the invoice front matter,
  2. the client entry,
  3. the top-level config.

due_days comes from the front matter, then the config. rate, unit and description on a client are only used to prefill new invoices (invgen new and Ctrl+N in the editor); they never change an existing invoice.

An invoice can also override any config key for itself with a config: block. See Per-invoice overrides.

Tax notes

Invoices without VAT usually need a legal mention. tax_note prints one under the totals; the presets are translated into every supported language:

PresetEnglish text
reverse_chargeReverse charge: VAT to be accounted for by the recipient (Article 196 of Council Directive 2006/112/EC).
exemptExempt from VAT.
outside_scopeOutside the scope of VAT.

Any other value is printed as written, and tax_note: false in an invoice drops the client or config note. To reword a preset, override its label (tax_note_exempt, for example) under labels:. These are standard wordings, not legal advice; check what your jurisdiction requires.

invgen build prints a warning (and the editor shows a notice after export) when an invoice charges no tax, has no tax_note and the client has tax lines. That is the typical cross-border B2B case that needs the reverse charge mention.

Invoice numbers

Numbers have the shape <prefix>-<year>-<seq>, for example EINV-2026-14. The sequence is global: it keeps counting across years (EINV-2025-13 is followed by EINV-2026-14). To find the next number invgen scans invoices_dir and up to two levels of subfolders for .md and .pdf files named <prefix>-YYYY-N..., takes the highest N and adds one. Per-year folders such as Invoices/2025/ are therefore fine.

Changes take effect

The CLI reads the config on every command (and invgen watch on every rebuild). The editor reads it once at startup, so restart the editor after changing the config.

Invoice markdown format

An invoice is a markdown file with YAML front matter. Static data (who you are, your bank, your clients) lives once in ~/.config/invgen/config.yaml; the invoice file only says what changes month to month.

---
number: EINV-2026-23          # optional: auto = next number after the highest in the invoices dir
date: 2026-11-02              # optional: defaults to today
due: 2026-11-16               # optional: or `due_days: 14`, or `false` to hide it
status: pending               # pending | paid | overdue | draft
paid_on: 2026-11-20           # optional: when it was paid (`invgen paid` writes it)
client: northwind       # key into config `clients:`  ...or an inline `to:` block
currency: EUR                 # optional: falls back to client currency, then config default
tax_rate: 0                   # percent; optional, falls back to client, then config
tax_label: VAT                # optional: defaults to the translated "VAT" label
tax_note: reverse_charge      # optional: legal mention under the totals (presets or free text)
accent: "#111827"             # optional
language: en                  # optional: en, es, de, fr, it, pt, nl
template: my-invoice.typ      # optional: custom typst template (docs/TEMPLATES.md)
---

# Senior Software Engineer
October 2026 period

| Description              | Qty | Unit | Rate   |
|--------------------------|-----|------|--------|
| Senior Software Engineer | 21  | days | 450.00 |

Any other paragraph becomes a note under the table.

Body rules

  • Items table: the first markdown table. Columns are matched by header name (case-insensitive, anything after ( ignored, so Rate (EUR) works): description/item/service, qty/quantity, unit, rate/price/unit price, optional detail, optional tax/vat (also tax rate, vat %…). A Days or Hours header is a quantity column that also sets the unit. Other columns (e.g. Total) are ignored; totals are always computed. Description, quantity and rate columns are required. Fully empty rows are skipped. Qty may be written 21 days (the unit is taken from it if there is no unit column or the unit cell is empty). Later tables are ignored.

  • Per-line tax rate: a Tax (or VAT) column gives each row its own rate in percent (21, 21%, 10 %, 0%); an empty cell uses the invoice tax_rate. In a list item, add , tax 10% (or , vat 10%, ; tax: 10%) at the end of the first line: - Training: 2 days @ 600, tax 10%. Rates must not be negative.

    | Description | Qty | Rate | Tax |
|-------------|-----|------|-----|
| Consulting  | 21  | 450  |     |
| Training    | 2   | 600  | 10% |
| Books       | 3   | 40   | 0%  |

  • Numbers accept 1,234.50 (, is only a thousands separator in groups of three, . is the decimal point; 1.234,50 is an error). A leading or trailing currency symbol/code is ignored: EUR 450, €450, 450 EUR. Negative rates are allowed (discounts). Numbers are kept as exact decimals (no binary floating point), so 0.1 is exactly 0.1. See Totals and rounding.

  • List items are an alternative to a table, used only when the document has no table: - Senior Software Engineer: 21 days @ 450 (@ or x). A list is an items list when its first entry has that shape; then every entry must have it. The detail is the item’s continuation lines (indented text under it) and/or its nested list entries (joined with ; ). Lists whose first entry is not item-shaped, and lists under a Notes heading, become notes (one note per entry). Lists may nest at most 64 levels deep; deeper nesting is an error.

  • Headings are ignored for data (they are for you), except a heading named Notes whose following paragraphs and lists become notes (until the next heading).

  • Lead paragraph: a paragraph directly after a (non-Notes) heading and before the items becomes the detail of the item when the invoice has exactly one item and that item has no detail of its own. In every other case it is a regular note. This is what turns October 2026 period in the example above into the item detail.

  • Paragraphs outside the table/list become notes, in order (inline markdown stripped to text, line breaks joined with spaces). HTML comments, code blocks, quotes and rules are ignored, so <!-- ... --> is a safe place for remarks.

  • An invoice without items is an error. Errors carry the 1-based line in the whole file (front matter included).

Totals and rounding

All amounts are computed with exact decimal arithmetic, and there is one rounding rule: round to cents, half away from zero (1.005 -> 1.01, -1.005 -> -1.01, 1.004 -> 1.00). It is applied in this order:

  1. Line total = quantity x rate, rounded to cents. 7.5 hours @ 133.33 is 999.975, shown as 999.98.
  2. Subtotal = the exact sum of the rounded line totals (no further rounding).
  3. Tax = subtotal x tax_rate / 100, rounded to cents. 1,000.99 at 7.7% is 77.07623, shown as 77.08. With per-line rates, the lines are grouped by rate: each rate’s base is the exact sum of its rounded line totals, its tax is base x rate / 100 rounded once to cents, and the invoice tax is the sum of the per-rate taxes. With a single rate this is exactly the rule above.
  4. Total = subtotal + tax.

So the line totals shown on the invoice always add up to the subtotal, the per-rate bases add up to the subtotal, and subtotal plus tax always equals the total, to the cent. When an invoice uses more than one rate, the PDF shows the rate under each line’s price and one totals row per rate (VAT 21%, with its taxable amount) instead of the single VAT (21%) row. Rates and quantities with more than two decimals are used at full precision in step 1 and only displayed rounded (quantities show at most two decimals, trailing zeros dropped). An invoice whose amounts exceed about 7.9e28 is an error.

Front matter resolution

  • No front matter at all is fine: everything takes its default. Unknown keys are ignored.
  • currency, tax_rate: front matter, then the client, then the config. tax_rate is a percent (21, 7.7 or "21%"); the same forms work for tax_rate and rate in the config.
  • client: must be a key of clients: in the config (the error lists the known ones). Without client: and without to:, the recipient is empty.
  • number: when absent, the next number from the invoices dir (see below). Prefer writing it explicitly (invgen new does): an auto number for a file that already lives in the invoices dir would count the file itself (or its PDF) and skip a number.
  • date: YYYY-MM-DD, default today. due: explicit date, else date + due_days (front matter due_days, else config due_days). due: false (or due: none) leaves the due date off the invoice.
  • status: pending (default), paid, overdue, draft; case-insensitive. The PDF always shows the status as written. invgen list and the editor sidebar show an effective status instead: a pending invoice whose due date has passed shows as overdue with the days late (overdue 12d). Any other written status wins, and an invoice without a due date (due: false) is never overdue automatically.
  • paid_on: YYYY-MM-DD, the day the invoice was paid. Optional and not printed on the PDF; invgen list shows it next to a paid status (paid 2026-11-20). invgen paid sets status: paid and paid_on for you, and invgen status with any other status removes it. Both change only those front matter lines.
  • signature: defaults to from.name; false hides it, a string replaces it.
  • tax_label defaults to the tax label of the invoice language (VAT, IVA, USt., TVA, Btw…); accent defaults to #111827 (#rgb or #rrggbb).
  • language: front matter, then the client, then the config, default en. Supported: en, es, de, fr, it, pt, nl (case-insensitive; a region suffix such as fr-BE is accepted and ignored). Any other value is an error listing these. The language changes every label on the invoice (headings, column names, status); dates and amounts keep their format.
  • template: front matter, then the config; none means the built-in template.
  • tax_note: front matter, then the client, then the config. A legal mention printed under the totals. Presets are translated into the invoice language: reverse_charge (reverse charge, Article 196 of Council Directive 2006/112/EC), exempt (exempt from VAT) and outside_scope (outside the scope of VAT); any other text is printed as written. tax_note: false on an invoice drops a client or config note. The preset texts are labels (tax_note_reverse_charge, tax_note_exempt, tax_note_outside_scope), so labels: in the config can reword them. They are standard mentions, not legal advice: check what your jurisdiction requires. invgen build (and the editor, on export) warns when an invoice charges no tax, sets no tax_note and the client has tax lines (such as a VAT ID).

Branding and languages

  • Logo: from.logo (SVG, PNG, JPEG, GIF or WebP) is drawn top-left in the header, scaled to fit 14 mm high by 60 mm wide with its aspect ratio kept. Set it in the config (from: then logo: logo.svg) or per invoice with from: / config: from: in the front matter; logo: null removes it for one invoice. A missing or unreadable file, or one that is not the image type its extension says, is an error naming the path.
  • Paths (from.logo, template) may start with ~. Relative paths are resolved against the directory of the config file, wherever they are written (config or front matter). In the Flatpak build, keep these files in the config directory (~/.config/invgen) or under ~/Documents, which the sandbox can read.
  • Labels: labels: in the config replaces single labels whatever the language, e.g. labels: {bill_to: Customer, tax: Sales tax}. The keys are listed in TEMPLATES.md; a key a language does not define falls back to English. Use config: labels: in the front matter to change one invoice only.
  • Templates: see TEMPLATES.md for writing your own and the data it receives. invgen template --export FILE.typ writes the built-in one.

Front matter overrides

Any of from:, to:, payment: may be given inline using the same shape as the config (name, address: [..], tax: [..], email, phone / holder, iban, bic, notes). Inline values replace the config ones field by field.

Overriding any config key: config:

A config: block takes the exact shape of config.yaml and is deep-merged over it for this invoice only. Mappings merge key by key, while scalars and lists replace. Set a value to null to remove an optional field (phone, email, a client’s tax_rate…).

---
client: northwind
config:
  number_prefix: INV        # auto-numbering for this invoice uses INV-...
  due_days: 30
  from:
    name: Morgan Studio     # other `from` fields (address, tax...) are kept
    phone: null             # hide the phone on this invoice
  payment:
    iban: CH93 0076 2011 6238 5295 7   # bic and holder are kept
  clients:
    northwind:
      currency: CHF
      address: [Bahnhofstrasse 1, "8001 Zurich", Switzerland]
---

The block edits the config itself, so the usual precedence then applies to the merged result: top-level front matter keys (currency, tax_rate, due_days, from:, to:, payment:) win, then the client entry, then the global keys. So a global tax_rate in the block does not beat a client’s own tax_rate; override it under clients: (or set it to null there) or use the top-level tax_rate: key. An invalid override is reported at the config: line.

Sequence numbers are global and monotonically increasing across years (EINV-2025-13 is followed by EINV-2026-14). The next number scans the invoice library (see below) for <prefix>-YYYY-N*.md / .pdf files, with N padded or not (EINV-2025-1, EINV-2025-02), takes the highest N of any year plus one and formats it with at least two digits: EINV-2026-01 for an empty directory. ~ in invoices_dir is expanded; the default is ~/Documents/Invoices.

The invoice library is invoices_dir plus up to two levels of subfolders (Invoices/2026/, Invoices/clients/acme/); hidden folders such as .git are skipped. invgen list, the editor sidebar and next-number scanning all use it.

The editor’s first-run setup and its Clients window write to this file in place: only the lines of the keys they change are rewritten (a key’s trailing # comment is kept), new keys go at the end of their block, and everything else stays byte for byte. They write values in the same style as above (plain scalars, quoted when YAML would read them as something else, lists as [a, b]). Client keys must be plain YAML keys: letters, digits, -, _ and ., starting with a letter or digit. Before writing, the result is parsed again and checked; the previous file is kept as config.yaml.bak. Files the editor cannot change safely (flow mappings like clients: {acme: {...}}, anchors and aliases, tags, several documents) are never rewritten; edit those by hand.

Command line

invgen [--config PATH] [COMMAND]

With no command, invgen opens the editor. invgen --help and invgen COMMAND --help print the built-in help, invgen --version the version.

Global options

OptionMeaning
--config PATHUse this config file instead of ~/.config/invgen/config.yaml. Accepted before or after the command name.
INVGEN_CONFIG=PATHEnvironment variable with the same effect. --config wins when both are set.
NO_COLORSet to any value to turn off colored output. Colors are also off when the output is not a terminal.

Errors in an invoice are reported compiler style, so editors and terminals can jump to them:

invoices/EINV-2026-23.md:9: error: unknown status `sent` (use pending, paid, overdue or draft)

invgen edit [FILE]

Opens the editor. invgen alone does the same.

  • With FILE, opens that invoice. If FILE does not exist yet, the editor starts a new invoice that will be saved to that path.
  • Without FILE, reopens the last file you worked on, or starts a new invoice.

invgen new [--client KEY] [--open]

Creates the next invoice in invoices_dir and prints its path.

OptionMeaning
--client KEYClient key from the config. Default: the first client (in alphabetical order of keys). An unknown key is an error that lists the known ones.
--openOpen the new file in the editor afterwards.

The file is named <number>.md, where the number is the next free number. invgen refuses to overwrite an existing file. The template contains:

  • front matter with number, today’s date, due_days, status: pending and client, plus commented hints for currency, tax_rate and signature;
  • a heading with the client’s description and the previous month as the period, for example October 2026 period;
  • one table row with the client’s description, unit and rate, and the number of weekdays of the previous month as the quantity.

With no clients in the config, the template has an inline to: block to fill in instead.

invgen new --from NUMBER|last [--client KEY] [--open]

Duplicates an existing invoice for recurring work: the copy keeps the items table or list, the notes, the front matter overrides and your formatting, and gets the next free number. It is written to invoices_dir like invgen new and its path is printed.

ArgumentMeaning
--from NUMBERThe invoice to copy: its number (EINV-2026-23), the bare sequence number (23), or a file path.
--from lastThe highest-numbered invoice in the library, or the highest one with client: KEY when --client KEY is given. --client only works together with --from last.

The copy changes only what belongs to one invoice:

  • number is the next free number and date is today;
  • an explicit due: date is removed, so the due date is computed again from due_days (due: false and due_days are kept);
  • status becomes pending and paid_on is removed;
  • in the body, a month with its year (October 2026, Oct 2026) or a YYYY-MM period (2026-10) that refers to the source invoice’s month or the month before it moves forward by the number of months since the source date (at least one): October 2026 period becomes November 2026 period, and December 2026 becomes January 2027. Full dates such as 2026-10-01 and other months are left alone.

Quantities are copied as they are, so check the number of days.

invgen build FILE.md [-o OUT.pdf] [--png DIR]

Renders one invoice.

OptionMeaning
-o, --output OUT.pdfWhere to write the PDF. Default: <number>.pdf in the same folder as FILE.md. Missing parent folders are created.
--png DIRAlso write a PNG of every page into DIR (144 dpi): <number>.png, or <number>-1.png, <number>-2.png, … for multi-page invoices.

On success it prints one line with the number, client, total and output path. On a parse error it prints the error and exits with status 1.

invgen watch FILE.md [-o OUT.pdf]

Builds the PDF once, then again every time FILE.md is saved, until you press Ctrl+C. The config is read again on every rebuild, so config edits are picked up too. A failed build prints the error and keeps watching. -o works as in build. See the watch mode recipe.

invgen list

invgen list [--year YYYY] [--client KEY|NAME] [--status STATUS]... [--unpaid] [--format table|csv|json]

Prints a table of the invoices in invoices_dir (and up to two levels of subfolders), in issue order:

NUMBER        DATE        CLIENT                     TOTAL  STATUS
EINV-2026-20  2026-07-01  Northwind Labs SL  EUR 10,350.00  overdue 94d
EINV-2026-21  2026-08-01  Northwind Labs SL   EUR 9,450.00  overdue 63d
EINV-2026-22  2026-10-01  Northwind Labs SL  EUR 12,450.90  paid
2026 total                                   EUR 32,250.90

OUTSTANDING  NOT DUE YET  1-30 DAYS  31-60 DAYS   61+ DAYS      TOTAL
EUR                 0.00       0.00        0.00  19,800.00  19,800.00

After each year it prints that year’s total, one line per currency. Below the table comes the outstanding balance: the total of the invoices whose effective status is pending or overdue, per currency, split by days past the due date (not due yet, 1-30, 31-60, 61 or more). Invoices without a due date count as not due yet. Drafts and paid invoices are not outstanding.

OptionMeaning
--year YYYYOnly invoices dated in that year.
--client KEY|NAMEOnly one client: a client key from the config, or part of the client name. Case-insensitive.
--status STATUSOnly invoices with that effective status: pending, paid, overdue or draft. Repeat it to allow several (--status pending --status overdue).
--unpaidOnly unpaid invoices, the same as --status pending --status overdue.
--format FORMATtable (default), csv or json. See Export.

Filters combine: invgen list --year 2026 --client northwind --unpaid shows what Northwind still owes for 2026. The yearly totals and the outstanding balance only count the invoices shown.

Files that fail to parse are reported on stderr as skipped: with their error, and the command then exits with status 1 (after printing the table), which makes it usable as a check in scripts.

Export

--format csv writes RFC 4180 CSV with a header row; --format json writes a JSON array with the same fields plus the line items. Amounts are exact decimal strings with two decimals (9450.00), never floating point numbers. Only the data goes to stdout, so it can be piped or redirected:

invgen list --year 2026 --format csv > invoices-2026.csv
invgen list --unpaid --format json | jq -r '.[] | "\(.number) \(.total)"'

The fields are documented in docs/EXPORT.md.

invgen check [--strict]

Scans the library and reports problems that matter for bookkeeping, compiler style, one per line:

invoices/EINV-2026-23.md:2: error: duplicate number EINV-2026-23 (also in invoices/2026/EINV-2026-23.md)
invoices/EINV-2026-27.md:2: warning: gap in the EINV sequence before EINV-2026-27: 25-26 missing
invoices/EINV-2026-28.md:3: error: EINV-2026-28 is dated 2026-09-01, before the lower number EINV-2026-27 (2026-10-01)
28 invoice(s) checked: 2 error(s), 1 warning(s)

Errors:

  • a file that fails to parse;
  • a duplicate number, or the same sequence number used twice under one prefix (sequences are global across years, so EINV-2025-5 and EINV-2026-05 collide);
  • a higher number dated before a lower one (drafts are ignored here);
  • an invoice whose client has no name.

Warnings:

  • a gap in the sequence of a prefix (between its lowest and highest number); a number that only exists as a PDF in the library fills its place;
  • an invoice without number: in its front matter (it gets an automatic one each time it is parsed, so it is left out of the sequence checks);
  • a number that does not look like PREFIX-YYYY-N, or whose year differs from the invoice date;
  • a sender without tax lines (from: tax:).

It exits with status 0 when there are no errors and 1 otherwise. Warnings alone do not fail, unless --strict is given. See the pre-commit hook recipe.

invgen paid FILE|NUMBER [--on YYYY-MM-DD]

Marks an invoice as paid: sets status: paid and paid_on: in its front matter. Only those lines change; comments, key order and the body stay byte for byte as they were (a missing front matter block is created).

FILE|NUMBER is a path, or an invoice number looked up in the invoice library: the full number (EINV-2026-23, matched against the front matter number and the file name) or the bare sequence number (23). No match, or more than one, is an error.

OptionMeaning
--on YYYY-MM-DDThe payment date. Default: the paid_on already in the file, else today.

invgen status FILE|NUMBER STATUS

Sets the written status to pending, paid, overdue or draft, editing only that line. paid works like invgen paid without --on; any other status removes paid_on.

invgen config [--edit]

Prints the path of the config file in use. If the file does not exist, it is created first with commented placeholders.

OptionMeaning
--editOpen the file in $VISUAL, else $EDITOR, else nano. When the editor exits, the file is validated and any error is shown as a warning (exit status 1).

invgen template --export [PATH] [--force]

Writes the built-in typst template to PATH (or prints it when PATH is left out), as a starting point for a custom template:. An existing file is only replaced with --force. The data a template receives is documented in TEMPLATES.md.

Exit status

0 on success, 1 on any error (bad arguments, unreadable files, a parse error, a skipped file in list, problems found by check, an invalid config after config --edit).

The editor

invgen (or invgen edit FILE) opens a native window with three parts: the invoice library on the left, the markdown editor in the middle and a live preview of the PDF on the right.

Keyboard shortcuts

KeysAction
Ctrl+NNew invoice with the next number
Ctrl+OOpen an invoice
Ctrl+SSave
Shift+Ctrl+SSave as
Ctrl+EExport the PDF next to the markdown file
Shift+Ctrl+EExport the PDF to a location you choose
Ctrl+BShow or hide the invoice library
Ctrl+= (or Ctrl++)Zoom the preview in
Ctrl+-Zoom the preview out
Ctrl+0Fit the preview to the panel width
Ctrl+mouse wheelZoom the preview around the pointer

The toolbar buttons do the same things and show their shortcut on hover.

Writing

The editor highlights the front matter, headings, tables, lists and numbers. Write the invoice as described in Invoice format; a new document (Ctrl+N) starts from the same template as invgen new, for the first client in your config.

Below the editor a status line reports the state of the preview:

  • Preview up to date when the text parses and renders.
  • Line N: message when there is a mistake. The line is highlighted in the editor; click the message to jump to it.

The window title shows a dot in front of the file name while there are unsaved changes.

Live preview

The preview re-renders shortly after you stop typing. It shows exactly what the exported PDF will look like. While the text has an error, the last good preview stays on screen with a banner that repeats the error, so the page does not flicker while you type.

Above the preview a bar shows the invoice total, number, status and client, the zoom level, a Fit width button and the page count. Drag the divider between editor and preview to resize them; double click it to restore the default split.

Saving and exporting

  • Save (Ctrl+S) writes the markdown. A new, untitled invoice is saved straight into invoices_dir as <number>.md when that name is free; otherwise a save dialog opens.
  • Export PDF (Ctrl+E) writes <number>.pdf next to the markdown file (or into invoices_dir for an untitled invoice). The file name always follows the number in the current text. Right click the button, or press Shift+Ctrl+E, to pick another location.
  • Open PDF opens the last export in your PDF viewer. The notification shown after an export has an Open button too.

Opening another file, starting a new one or closing the window with unsaved changes asks whether to Save, Discard or Cancel.

Invoice library

The sidebar lists the .md files directly inside invoices_dir, newest first, with number, client, total and a colored status. Hover an entry to see its path and date; click it to open it. Files that fail to parse are still listed, marked “could not parse”.

Right-click an entry for Mark as paid, Set status (pending, paid, overdue, draft) and Duplicate. The status actions edit only the status and paid_on lines of the file; if that file is open with unsaved changes, nothing is written and a message asks you to save first. Duplicate works like invgen new --from and opens the new invoice. The list refreshes when files in the folder change, including changes made by other programs.

Toggle the sidebar with Ctrl+B or the button in the top left corner.

Files changed outside the editor

If the open file changes on disk (for example after a git pull, or an edit in another editor), invgen reloads it. If you have unsaved edits, it keeps your edits and tells you the file changed on disk instead.

Drag and drop

Drop a .md, .markdown or .txt file onto the window to open it.

Themes and remembered settings

The theme button cycles between dark, light and following the system theme. The editor remembers the theme, the split position, the zoom, whether the sidebar is shown, the window size and the last opened file.

Config

The editor reads the config once at startup. A broken config is reported in a notification and the editor falls back to defaults. Restart the editor after editing the config. It honors --config and INVGEN_CONFIG like the CLI.

Monthly billing for one client

A contractor bills one client once a month for the days worked in the previous month. Set the client up once, then each month takes a minute.

Set up the client once

Give the client the defaults the template should use:

# ~/.config/invgen/config.yaml
due_days: 14

clients:
  northwind:
    name: Northwind Labs SL
    address: ["Calle Mayor, 12", Madrid, "28001", Spain]
    tax: ["Tax ID: B12345678"]
    rate: 450
    unit: days
    description: Senior Software Engineer

Every month

At the start of the month:

invgen new --client northwind --open

On 2 November 2026 this creates a file like:

---
number: EINV-2026-23   # leave out to auto-number from ~/Documents/Invoices
date: 2026-11-02
due_days: 14                # or an explicit `due: YYYY-MM-DD`
status: pending             # pending | paid | overdue | draft
client: northwind
# currency: EUR               # defaults to the client, then the config
# tax_rate: 0                 # percent
# signature: false           # hide the signature, or set a custom text
---

# Senior Software Engineer
October 2026 period

| Description | Qty | Unit | Rate |
|-------------|-----|------|------|
| Senior Software Engineer | 22 | days | 450.00 |

<!-- Paragraphs below the table become notes on the invoice, e.g.
     "Payment within 14 days. Thank you!" -->

The quantity is the number of weekdays in October. Adjust it for holidays and days off, add rows for anything extra (on-call hours, expenses) and press Ctrl+E to export EINV-2026-23.pdf. Because the invoice has a single item, the line October 2026 period under the heading is printed as that item’s detail.

Prefer the terminal? Edit the file in any editor and run invgen build ~/Documents/Invoices/EINV-2026-23.md.

Next month, start from this invoice instead of the template, so extra rows and notes come along:

invgen new --from last --client northwind --open

The copy gets the next number, today’s date and status: pending, and October 2026 period becomes November 2026 period.

When the client pays

invgen paid EINV-2026-23            # or: invgen paid 23 --on 2026-11-20

This sets status: paid and paid_on: in the front matter and leaves the rest of the file as it was. In the editor, right-click the invoice in the sidebar and choose Mark as paid. invgen list then shows the invoice as paid with the date. invgen never changes the status on its own; mark late invoices overdue yourself if you want them to stand out in the list and on the PDF.

A standing note

For a note that every invoice to this client should carry (a purchase order number, a payment reference), add it to the payment notes in the config:

payment:
  holder: ALEX MORGAN
  iban: DE89 3704 0044 0532 0130 00
  bic: COBADEFFXXX
  notes: ["Please quote the invoice number as the transfer reference"]

For a note on a single invoice, write a paragraph below the table.

Multiple currencies

invgen prints amounts in whatever currency an invoice uses. It does not convert between currencies; each invoice is in exactly one currency.

A default per client

Set the global default once and override it for the clients that pay in something else:

currency: EUR

clients:
  northwind:
    name: Northwind Labs SL
    address: ["Calle Mayor, 12", Madrid, "28001", Spain]
  contoso:
    name: Contoso Ltd
    address: [1 Example Street, London, "EC1A 1AA", United Kingdom]
    currency: GBP
    rate: 380
    unit: days
  fabrikam:
    name: Fabrikam AG
    address: [Bahnhofstrasse 1, "8001 Zurich", Switzerland]
    currency: CHF
    tax_rate: 8.1

Invoices for contoso are in GBP, those for fabrikam in CHF with 8.1% tax, everything else in EUR. invgen new --client contoso already writes the GBP default as a hint in the front matter.

One invoice in another currency

Set currency in the front matter; it beats the client and the config:

---
client: northwind
currency: USD
---

The currency is printed as a code in front of every amount (USD 9,450.00), so any code or text works.

Writing amounts

Rates can carry a currency symbol or code, which is ignored when reading the number: 450, EUR 450, €450 and 450 EUR all mean 450. The currency of the invoice still comes from the front matter, client or config, never from the table.

Totals across currencies

invgen list never adds different currencies together. The yearly summary has one total line per currency:

2026 total                                   CHF 4,860.00
2026 total                                   EUR 32,250.90
2026 total                                   GBP 7,600.00

The outstanding balance below the table also has one line per currency.

Per-invoice overrides

Most invoices only need client: and a table. When one invoice has to differ from the config, override just that one; the config stays untouched.

Top-level front matter keys

The common cases have their own keys:

---
client: northwind
currency: USD            # instead of the client or config currency
tax_rate: 21             # percent, also "21%"
tax_label: IVA           # instead of VAT
due: 2026-12-31          # explicit due date; or due_days: 30; or due: false to hide it
accent: "#0f766e"        # accent color of the PDF
signature: false         # hide the signature, or a string to replace it
---

Replacing the sender, recipient or bank

from:, to: and payment: take the same fields as in the config and replace them field by field:

---
client: northwind
to:
  address: [Paseo de la Castellana 1, Madrid, "28046", Spain]   # new billing address, name kept
payment:
  iban: CH93 0076 2011 6238 5295 7                              # holder and bic kept
---

A one-off client that is not in the config at all can be written inline with to: and no client::

---
to:
  name: Tailspin Toys
  address: [10 Example Road, Dublin, Ireland]
  tax: ["VAT ID: IE1234567X"]
---

Overriding any config key: config:

The config: block takes the shape of config.yaml and is merged over it for this invoice only. Mappings merge key by key, scalars and lists replace, and null removes an optional value:

---
client: northwind
config:
  number_prefix: INV
  from:
    name: Morgan Studio      # trading name for this client; address and tax kept
    phone: null              # no phone on this invoice
  clients:
    northwind:
      currency: CHF
---

Precedence still applies after the merge: top-level front matter keys win over the client entry, which wins over global keys. So to change the tax rate for a client that has its own tax_rate, override it under clients: or use the top-level tax_rate: key, not a global tax_rate inside config:.

The full rules are in Invoice format.

Keeping invoices in git

Invoices are small text files, so a git repository gives you history, backups and a record of when each invoice was issued and paid.

Set up

Keep the markdown in git and treat the PDFs as build output that can always be regenerated:

cd ~/Documents/Invoices
git init
printf '*.pdf\n' > .gitignore
git add .gitignore *.md
git commit -m "Invoices so far"

If you send PDFs to clients and want the exact file you sent on record, commit the PDFs too instead of ignoring them. The output for a given markdown file and config only changes when invgen’s template changes.

Consider keeping the config next to the invoices so the two travel together, and point invgen at it:

mv ~/.config/invgen/config.yaml ~/Documents/Invoices/config.yaml
export INVGEN_CONFIG=~/Documents/Invoices/config.yaml   # in your shell profile

The config holds your bank details and client addresses, so keep such a repository private.

Organize by year

The next-number scan and invgen list both look two levels deep, so per-year folders work:

Invoices/
  config.yaml
  2025/EINV-2025-12.md
  2025/EINV-2025-13.md
  EINV-2026-14.md

invgen new and the editor create new files at the top of invoices_dir, and the editor sidebar lists only that top level, so move older years into their folders once they are closed.

Check before committing

invgen check exits with status 1 when an invoice fails to parse, a number is used twice, or a higher number is dated before a lower one, so it works as a pre-commit hook:

#!/bin/sh
# .git/hooks/pre-commit (make it executable: chmod +x .git/hooks/pre-commit)
exec invgen check

Use invgen check --strict to also block commits on warnings, such as a gap in the numbering or a sender without tax lines. If your config lives outside the repository, set INVGEN_CONFIG in the hook (hooks do not read your shell profile):

#!/bin/sh
export INVGEN_CONFIG="$HOME/Documents/Invoices/config.yaml"
exec invgen check --strict

Note that the hook checks the files in the working tree, not only what is staged.

Commit messages that tell the story

A commit per event keeps git log readable as a ledger:

git add EINV-2026-23.md && git commit -m "Issue EINV-2026-23 (Northwind, October)"
git commit -am "EINV-2026-23 paid"

Watch mode with your own editor

If you prefer Vim, Emacs, VS Code or any other editor over the built-in one, invgen watch gives you the same edit and preview loop.

invgen watch ~/Documents/Invoices/EINV-2026-23.md

It builds the PDF once, then again every time the file is saved:

10:41:07 built EINV-2026-23  Northwind Labs SL  EUR 9,900.00  /home/alex/Documents/Invoices/EINV-2026-23.pdf
watching /home/alex/Documents/Invoices/EINV-2026-23.md (Ctrl+C to stop)
10:42:15 built EINV-2026-23  Northwind Labs SL  EUR 9,450.00  /home/alex/Documents/Invoices/EINV-2026-23.pdf

Open the PDF in a viewer that reloads on change (for example Evince, Okular or zathura) next to your editor, and every save updates the page.

Details:

  • Mistakes are printed as file:line: error: message and watching continues; the last good PDF stays in place.

  • The config is read again on every rebuild, so you can tune the config and the invoice at the same time.

  • Editors that save by writing a temporary file and renaming it are handled.

  • -o OUT.pdf writes the PDF somewhere else, for example a fixed preview file that your viewer keeps open:

    invgen watch EINV-2026-23.md -o ~/preview.pdf

Jumping to errors

Because errors use the file:line: format, editors that understand compiler output can jump to them. In Vim:

:set makeprg=invgen\ build\ %
:make

FAQ and troubleshooting

Where is my config?

Run invgen config. It prints the path in use (and creates a starter file there if none exists). In order, invgen uses:

  1. --config PATH on the command line,
  2. the INVGEN_CONFIG environment variable,
  3. $XDG_CONFIG_HOME/invgen/config.yaml, which is ~/.config/invgen/config.yaml on most systems.

The Flatpak always uses ~/.config/invgen/config.yaml on the host, not the private ~/.var/app/io.github.ldolberg.invgen/config folder, so the native build and the Flatpak share one config.

I changed the config but the editor does not show it

The editor reads the config once at startup. Close and reopen it. The CLI reads the config on every command, and invgen watch on every rebuild.

A config key seems to have no effect

Unknown keys are ignored silently, so check the spelling against Configuration. Also check precedence: a value in the invoice front matter or in the client entry beats the global one.

Flatpak file access

The Flatpak sandbox can read and write:

  • ~/Documents (the default invoices_dir is ~/Documents/Invoices),
  • ~/.config/invgen (the config).

Files anywhere else can still be opened and saved from the editor through the file chooser (Ctrl+O, Shift+Ctrl+S, Shift+Ctrl+E), which grants access to the chosen file. What does not work inside the sandbox:

  • an invoices_dir outside ~/Documents: invgen new, invgen list, the sidebar and automatic numbering cannot see it;
  • passing a path outside ~/Documents on the command line, for example flatpak run io.github.ldolberg.invgen build ~/work/invoice.md.

To allow another folder, grant it with an override, for example:

flatpak override --user --filesystem=~/Invoices io.github.ldolberg.invgen

Or keep invoices under ~/Documents, or use the tarball or a source build, which have no sandbox.

Which fonts are used? Can I change them?

The PDF uses fonts embedded in invgen: Inter for all text and Mrs Saint Delafield for the signature. System fonts are never used, so a PDF looks the same on every machine and nothing needs to be installed. The fonts cannot be changed from the config today.

Inter covers Latin, Greek and Cyrillic scripts. Characters outside the bundled fonts (for example Chinese, Japanese, Arabic or emoji) will not render correctly.

The signature shows my name. How do I hide or change it?

The signature defaults to from.name. Set signature: false in the front matter to hide it, or signature: Alex M. to print other text.

Can invgen mark invoices overdue automatically?

No. The status is whatever the front matter says (pending by default). Change it to paid or overdue yourself.

The invoice number skipped one

If an invoice has no number: and lives in invoices_dir, the automatic number counts the file itself (or its PDF) and comes out one too high. Write the number explicitly; invgen new and the editor template do this for you.

invgen list prints “skipped” and exits with 1

Those files failed to parse. The message shows the file, line and problem. Fix them (or move unrelated .md files out of invoices_dir) and run it again.

The editor does not start

The editor needs a graphical session (Wayland or X11). Over SSH or in a plain terminal, use the CLI commands new, build, watch and list instead; they do not need a display.

Where do I report a bug or ask for a feature?

Open an issue at https://github.com/ldolberg/invgen/issues. Use dummy data in examples, never real client or bank details.
